Why score-first

Audio-first tools invent sound and leave you guessing the notes. Copyist starts with a song file — melody, chords and lyrics — and derives everything else from that score.

  • Audio-first generators

    A recording appears. Sheet music has to be guessed back out: wrong octaves, smeared rhythms, no chord names, lyrics that drift.

  • Copyist

    The score is the source of truth. The lead sheet, parts, MIDI and band audio all come from the same notes, so what you hear matches what is written.

What you get

From one song file: validated music you can print, play and rearrange — chosen by listening, not by reading notation.

  • Lead sheet, score and parts

    PDF and MusicXML for the lead sheet, full score and every player’s part — clefs, ranges and layout checked by validators.

  • A sampled band

    Piano, bass, drums, guitars, winds and more play the arrangement through sfizz. Stems and a gentle master for checking by ear.

  • Twenty-three styles

    Waltz, hymn, swing, bossa, Broadway, folk, rock and more. Gallery a song in every style that fits, then keep the one you like.

  • Write melodies from lyrics

    copyist write proposes several tunes with chords and fitted words. Listen to each band preview and keep one.

  • Transcribe a recording you own

    Turn a demo into a lead sheet: melody as sung, chords and lyrics under the notes, then every Copyist output follows.

  • Production takes that follow the score

    YuE2 performs band and singer together from the same notes. copyist follow checks the take sang what was written.

  • A local page and desktop shell

    copyist serve puts songs, scores and takes in the browser on your machine. A Tauri app wraps the same engine.

  • Built for people who don’t read music

    Choose by listening and plain-language checks. Anyone who does read music can still see and edit every note.

How it works

  1. 1

    Song file

    YAML with an ABC melody, chord symbols and lyrics — public domain or your own.

  2. 2

    Canonical score

    Validators check bars, lyrics, range, chords and prosody before anything is finished.

  3. 3

    Arrange, engrave, render

    Style patterns become parts; Verovio engraves PDF; the band (or YuE2) plays the notes.

Install and set up

Python 3.10 or later on macOS or Linux. Everything runs locally; models and instruments download when you ask for them.

1. Get the code

git clone https://github.com/Digital-Defiance/copyist.git
cd copyist
python -m venv .venv
source .venv/bin/activate   # Windows: .venv\Scripts\activate
pip install -e .

2. Build a song

pip install --no-deps tinysoundfont   # fallback SoundFont (optional)
copyist build songs/amazing-grace.yaml

Outputs land in out/amazing-grace/: lead sheet and band score as PDF, parts, MusicXML, MIDI, a preview WAV and a validation report.

3. Sampled instruments (recommended)

scripts/setup-sfizz.sh --instruments   # ~1.1 GB band pack

Then rebuild the same song to hear the concert grand, basses, kit and melody winds instead of the SoundFont fallback.

4. Open the local page

copyist serve

Opens http://127.0.0.1:8765/ — songs, score pages, band previews, writing and transcription. Nothing is loaded from the internet while you work.

Optional: production singer (YuE2)

scripts/setup-yue.sh                   # runtime + weights (GPU recommended)
copyist produce songs/amazing-grace.yaml
copyist follow songs/amazing-grace.yaml out/amazing-grace/production/production.wav

YuE2 weights are CC BY-NC 4.0, with permission for individual creators to sell their own songs. The page shows each licence before download.

Run the tests

python -m unittest discover -s tests
